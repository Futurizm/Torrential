# Torrential

**Torrential - minimalistic desktop torrent client.** Тёмный интерфейс в духе
Linear / Raycast, Node-движок на [WebTorrent](https://github.com/webtorrent/webtorrent),
живое обновление состояния по WebSocket. Интерфейс на русском и английском.

```
React + TypeScript + Tailwind  ──REST──▶  Node.js + WebTorrent  ──▶  BitTorrent-сеть
            ▲                              │
            └──────── WebSocket ───────────┘
```

---

## Быстрый старт

```bash
npm install
npm run dev          # движок :8787 + Vite :5273
```

Откройте <http://localhost:5273> и перетащите `.torrent` в окно (или вставьте magnet через `Ctrl+V`).

Продакшен-сборка (один процесс отдаёт и движок, и UI):

```bash
npm run build && npm start   # http://localhost:8787
```

Требуется **Node.js ≥ 22**.

## Сборка .exe (десктоп-приложение)

Оболочка — **Electron**. Движок (WebTorrent) запускается отдельным процессом,
но на рантайме самого Electron через `ELECTRON_RUN_AS_NODE=1`, поэтому второй
`node.exe` в сборку не попадает — нативные модули N-API совместимы с ним.

```bash
npm run desktop:dev     # собрать и запустить окно из исходников
npm run desktop:dist    # установщик + portable .exe в release/
```

Готовые файлы:

| Файл                                  | Что это                                  |
| -------------------------------------- | ---------------------------------------- |
| `release/Torrential-1.0.0-setup.exe`   | установщик NSIS (можно выбрать папку)   |
| `release/Torrential-1.0.0-portable.exe`| портативная версия, без установки      |

Как это устроено:

- `electron/main.cjs` — окно, выбор свободного порта, запуск движка, ожидание
  `/api/health`, graceful shutdown, лог в `%APPDATA%/Torrential/desktop.log`.
- `electron/preload.cjs` — три безопасных вызова в renderer (`isDesktop`,
  `info`, `revealDownloads`); `contextIsolation` включён, Node-интеграция выключена.
- `scripts/stage-engine.mjs` — собирает `.stage/engine`: скомпилированный сервер,
  статика и **только production-зависимости** (46 МБ вместо всех dev-зависимостей).
- `scripts/after-pack.cjs` — хук electron-builder: кладёт движок в `resources/engine`
  уже после распаковки приложения. Это обязательный обход: electron-builder
  вырезает `node_modules` из `extraResources`, а движку они нужны для резолва
  `express`/`ws`/`webtorrent` — без него установленное приложение не запустится.
- `scripts/make-icon.mjs` — генерирует `build/icon.ico` и `icon.png`
  (собственный PNG/ICO-кодек на zlib, без графических библиотек).

Первый запуск занимает ~10 с — Windows Defender сканирует 46 МБ новых файлов.
Второй и последующие — около 0,6 с.

В окне используется нативная шапка: на Windows поверх нашего TopBar рисуются
системные кнопки окна (`titleBarOverlay`), шапку можно перетаскивать мышью.
Кнопка «открыть папку» в настройках появляется только в десктопной версии.

Полезные команды:

```bash
npm run desktop:pack    # только распакованная папка (быстрая проверка)
npm run icon            # пересобрать иконку
```

Служебные скрипты:

```bash
node scripts/preview-icon.mjs build/icon.png   # ASCII-превью иконки
powershell -File scripts/shot-window.ps1       # скриншот окна приложения
npm run screenshots                           # скриншоты приложения для сайта
npx electron scripts/inspect-layout.cjs <порт> # метрики вёрстки в реальном окне
```

## Сайт

Лендинг с описанием Torrential лежит в отдельном проекте [`frontend/`](frontend) —
Next.js 15 (App Router) + TypeScript + Tailwind. Свой `package.json`, свои
зависимости, ничего общего с рантаймом приложения.

```bash
npm run site:dev      # http://localhost:3000
npm run site:build    # статическая генерация /ru и /en
npm run site:start    # предпросмотр сборки
```

Что внутри:

- две локали `/ru` и `/en` с собственными URL, `hreflang`, canonical и
  `sitemap.xml` — `/` редиректит на русскую версию;
- тёмная тема в стиле приложения (стекломорфизм, мягкие индиго-изумрудные
  блики, плавные появления), системный шрифт без внешних запросов;
- секции: первый экран, возможности, галерея скриншотов, стек, загрузка, FAQ;
- `robots.txt`, `sitemap.xml`, OG-теги и локализованная страница 404.

Скриншоты в `frontend/public/screenshots/` снимаются автоматически:

```bash
npm run screenshots   # трекер + сидер + движок, четыре состояния окна
```

Подробности, переменные окружения и то, как заменить картинки своими, — в
[`frontend/README.md`](frontend/README.md).

## Языки

Интерфейс полностью двуязычный: **русский** и **английский**.

- Переключатель — «Настройки → Язык интерфейса» (RU / EN).
- Выбор сохраняется в `localStorage` и переживает перезапуск.
- При первом запуске язык берётся из системной локали, при отсутствии выбора — русский.
- Нативные диалоги Electron (движок упал, не удалось запустить) тоже переводятся:
  renderer сообщает оболочке язык через IPC, оболочка помнит его в `userData/locale.txt`.
- Атрибут `<html lang>` обновляется, поэтому скринридеры читают правильный язык.

Как устроен перевод:

```
src/i18n/translations.ts   словари; русский — эталон, английский типизирован
                           Record<TranslationKey, string>, поэтому забытый
                           ключ ломает компиляцию, а не собе��ку
src/i18n/core.ts           подстановка {placeholders}, склонения, определение языка
src/i18n/index.tsx         React-контекст: useI18n() / useT()
```

Ошибки API приходят с машиночитаемым кодом (`invalid_magnet`, `duplicate`,
`metadata_pending`, …), а клиент показывает текст по коду из своего словаря —
поэтому сервер не знает про языки. Склонения («1 торрент / 2 торрента / 5 торрентов»)
считаются по правилам русского; в английском формы не меняются.

## API

### REST (мутации)

| Метод    | Путь                      | Назначение                                       |
| -------- | ------------------------- | ------------------------------------------------ |
| `GET`    | `/api/health`             | состояние сервера                                |
| `GET`    | `/api/torrents`           | список + глобальная статистика                   |
| `GET`    | `/api/torrents/:id`       | снимок (`?files=0` — без списка файлов)          |
| `POST`   | `/api/torrents`           | `{ magnet }` либо `{ file: { name, data(base64) } }` |
| `PATCH`  | `/api/torrents/:id`       | `{ action: 'pause' \| 'resume' \| 'check' }`     |
| `DELETE` | `/api/torrents/:id`       | удалить, `?deleteFiles=1` — вместе с данными     |
| `PUT`    | `/api/torrents/:id/files` | `{ indices: number[] }` — выбор файлов           |
| `GET/PUT`| `/api/settings`           | лимиты скорости и параметры движка               |

Ошибки возвращаются как `{ error, code }`: `code` — машиночитаемый идентификатор
(`invalid_magnet`, `invalid_torrent_file`, `duplicate`, `metadata_pending`,
`torrent_not_found`, …), по которому клиент показывает локализованный текст из
своего словаря.

### WebSocket `/ws`

Клиент → сервер: `sync`, `subscribe {id}`, `unsubscribe {id}`, `ping`.
Сервер → клиент: `sync` (полный снимок), `torrent` (дельта), `removed`, `settings`, `pong`, `error`.

Чтобы не гонять лишние килобайты, список файлов прикладывается к снимку **только для
торрентов, на которые клиент подписан** (подписка создаётся при открытии панели деталей).

## Настройки

Все параметры — через `.env` (шаблон в `.env.example`):

| Переменная                    | По умолчанию | Описание                                    |
| ----------------------------- | ------------ | ------------------------------------------- |
| `PORT`                        | `8787`       | порт HTTP/WS                                |
| `DOWNLOAD_DIR`                | `~/Downloads/Torrential` | куда складывать данные            |
| `TORRENTIAL_DOWNLOAD_LIMIT`   | `-1`         | лимит приёма, байт/с (`-1` — без лимита)   |
| `TORRENTIAL_UPLOAD_LIMIT`     | `-1`         | лимит отдачи, байт/с                        |
| `DHT`                         | `true`       | DHT-бутстрап                                |
| `UTP`                         | `true`       | µTP-транспорт (выключите, если блокируется)|
| `TRACKERS`                    | —            | доп. трекеры через запятую                 |
| `PERSIST`                     | `true`       | сохранять magnet-ссылки для восстановления  |
| `LOG_LEVEL`                   | `info`       | `debug` \| `info` \| `warn` \| `error`      |

Лимиты скорости и «Восстановление сессии» переключаются прямо в UI (вкладка «Настройки»).

## Как это работает

**Пауза.** У WebTorrent нет «настоящей» паузы передачи: `torrent.pause()` лишь
прекращает открывать новые соединения. Поэтому пауза реализована в три действия:
снятие выборки кусков (`deselect`), остановка новых соединений и явное
`wire.uninterested()` всем пирам. Последнее важно: WebTorrent считает нас
заинтересованными, пока у пира есть хоть один кусок, и без явного сообщения на
паузе продолжают долетать уже запрошенные куски — до ~900 КБ, что выглядит как
«пауза не работает». С явным `uninterested()` хвост сокращается примерно до 150 КБ
и поток встаёт за полсекунды. Возобновление пересобирает выборку и шлёт `interested`.

**Выбор файлов.** Выборка в BitTorrent действует на уровне **кусков**, а не файлов.
Соседние выбранные файлы склеиваются в диапазоны кусков (иначе на раздаче в
10 000 файлов будет 10 000 вызовов `select`), а файл, делящий куски с соседним,
скачается целиком — это отмечено подсказкой в панели деталей.

**Восстановление сессии.** При добавлении в `<DOWNLOAD_DIR>/.torrential/` пишется
magnet-ссылка (не `.torrent`: для magnet-источника `torrent.torrentFile` не содержит
info-секции и не является валидным файлом). При старте движок читает эти ссылки и
добавляет торренты обратно — данные на диске переиспользуются.

**Живые обновления.** Хаб рассылает дельты каждые 400 мс для активных торрентов и
раз в 5 с для «спящих» (пауза/ошибка/ожидание метаданных). Раз в ~10 с уходит полный
`sync` как страховка от потерянных кадров.

## Упаковка в десктоп

Интерфейс не использует Node-API: работа идёт через REST и WebSocket, поэтому
он одинаково запускается в браузере, в Electron и в любой другой оболочке
(Tauri, webview, удалённый хост). Готовую сборку `.exe` делает
`npm run desktop:dist` — см. раздел выше.

Если захотите Tauri: `beforeDevCommand: "npm run dev:server"`, а в рендерере
тот же `http://127.0.0.1:8787`; отдельный Node-sidecar придётся тянуть руками,
поэтому для этого проекта Electron проще.

## Тесты

```bash
npm test            # оба набора
npm run test:ui     # рендер интерфейса в jsdom, 42 проверки в двух языках
npm run test:e2e    # реальный magnet-торрент: скачивание, пауза/резюм, файлы, WS, рестарт
```

`test:e2e` поднимает локальный HTTP-трекер и сидер, запускает сервер на свободном
порту `8791` и проходит весь сценарий: magnet → старт загрузки → **пауза на живых
данных** (поток реально встаёт, замер «хвоста» уже запрошенных кусков) → резюм →
докачивание до 100 % → выбор 2 из 3 файлов → проверка → `.torrent`-файл → отказ
дубликата (409) и битого файла (400) → живые кадры по WebSocket → восстановление
после перезапуска движка → удаление с данными.

`test:ui` монтирует приложение в jsdom с фейковым движком, открывает панель
деталей (файлы приходят по подписке WebSocket), переключает язык RU → EN и
проверяет, что русские строки исчезли, а `<html lang>` обновился.

## Ограничения

- Только BitTorrent v1/v2 через WebTorrent: нет UDP-трекер-протокола вне DHT/LSD,
  нет magnet-поддержки BEP-9 и расширений protocol.
- «Раздача после завершения» есть, но без смены портов и seed-ratio.
- Нет magnet-ссылок из комментариев и `web seed`-очереди в UI.
- Выбор файлов работает на уровне кусков (см. выше) — это ограничение протокола,
  а не интерфейса.
